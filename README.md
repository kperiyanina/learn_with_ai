# LearnWithAI

LearnWithAI — приложение для создания персональных учебных планов с помощью
искусственного интеллекта. Пользователь указывает учебную цель, свой уровень,
срок, доступную нагрузку и предпочтения, после чего приложение формирует
структурированный план по неделям.

Текущая версия объединяет Streamlit-интерфейс для пользователей и отдельный
REST API на FastAPI. Данные хранятся в SQLite.

## Возможности

### Пользовательский интерфейс

- регистрация и вход по email и паролю;
- безопасное хеширование паролей;
- профиль пользователя;
- изоляция данных между пользователями;
- создание учебного плана через Groq API;
- валидация цели, уровня, количества недель и часов;
- дополнительные параметры плана:
  - интересы;
  - предпочтительный формат занятий;
  - доступные дни;
- автоматический переход в раздел «Мои планы» после создания плана;
- просмотр планов, недельных блоков и задач;
- отметка задач, теории и материалов как выполненных;
- генерация теории, практических инструкций и теста для блока;
- тестирование знаний с сохранением истории попыток;
- повторное прохождение теста после первой попытки;
- адаптивные рекомендации по прогрессу;
- удаление учебного плана с подтверждением;
- раздел статистики:
  - общий прогресс;
  - выполненные задачи;
  - пройденная теория;
  - результаты тестов;
  - изученные материалы;
  - учёт времени занятий;
- экспорт статистики в CSV с кодировкой UTF-8 с BOM для корректного открытия в
  Excel;
- раздел расписания с настройками дней, времени, часового пояса и напоминаний;
- вертикальная боковая навигация.

### REST API

API поддерживает Bearer-аутентификацию и проверяет владельца ресурсов.
Доступны следующие основные endpoints:

```text
GET   /health
POST  /auth/register
POST  /auth/login
GET   /users/me
PATCH /users/me
GET   /plans
GET   /plans/{plan_id}
POST  /plans
GET   /plans/{plan_id}/tasks
GET   /plans/{plan_id}/progress
PATCH /tasks/{task_id}
```

Интерактивная документация API доступна по адресу
`http://127.0.0.1:8000/docs`.

## Установка

Требуется Python 3.10 или новее.

Создайте виртуальное окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Создайте локальный файл `.env` на основе `.env.example`:

```powershell
Copy-Item .env.example .env
```

Затем укажите в `.env` собственный ключ `GROQ_API_KEY`. Файл `.env` не следует
добавлять в Git.

Основные переменные:

| Переменная | Назначение |
|---|---|
| `GROQ_API_KEY` | ключ AI-провайдера |
| `GROQ_MODEL` | используемая модель Groq |
| `AI_TIMEOUT_SECONDS` | таймаут AI-запроса |
| `AI_MAX_RETRIES` | число повторных попыток AI-запроса |
| `AI_FALLBACK_ENABLED` | разрешить локальный fallback |
| `DATABASE_PATH` | путь к SQLite-базе |
| `API_SECRET_KEY` | секрет подписи API-токенов |

## Запуск Streamlit-приложения

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

После запуска откройте в браузере:

```text
http://localhost:8501
```

Для обычной работы пользователя достаточно запустить Streamlit.

## Запуск REST API

```powershell
.\.venv\Scripts\python.exe -m uvicorn api:app --reload
```

Документация:

```text
http://127.0.0.1:8000/docs
```

API можно запускать отдельно, когда требуется подключение другого клиента:
веб-фронтенда, мобильного приложения, Telegram-бота или интеграционного
скрипта.

## Тестирование

Запуск полного набора тестов:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют доменную валидацию, локальную генерацию, операции базы данных,
материалы, прогресс, авторизацию и API. В текущем состоянии последний
проверенный набор содержит 28 тестов.

## Ограничения текущей версии

- основное хранилище — SQLite, а не PostgreSQL;
- миграции выполняются средствами текущего слоя SQLite, Alembic не используется;
- фоновые email- и push-уведомления пока не подключены;
- расписание сохраняется и используется как настройка интерфейса, но не запускает
  фоновые задания;
- расширенная аналитика, достижения, streak и графики требуют дальнейшей
  разработки;
- API учебных блоков, истории попыток и материалов пока не выделены в отдельные
  endpoints;
- production-развёртывание, HTTPS, Docker, резервное копирование и мониторинг
  не настроены.

Подробный журнал изменений находится в
[`DEVELOPMENT_LOG.md`](DEVELOPMENT_LOG.md), а план дальнейшей разработки — в
[`DEVELOPMENT_PLAN.md`](DEVELOPMENT_PLAN.md).

## Безопасность

- не храните реальные ключи и пароли в исходном коде;
- используйте отдельный секрет `API_SECRET_KEY` в production;
- не публикуйте файл `.env`;
- при раскрытии ключа Groq отзовите его и создайте новый;
- пользовательские планы, задачи и прогресс доступны только их владельцу.
